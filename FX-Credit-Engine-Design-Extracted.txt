Three Distributed Design Patterns
Architecture, Implementation & Trade-off Analysis
Design 1  Optimistic Local Cache + Async Correction
Design 2  Token Bucket with Centralised Top-Up
Design 3  Atomic Broadcast / Total Order via Aeron Cluster
Audience: Senior Engineers · Architects · AI Developers
Version 1.0   ·   21 June 2026
1. Introduction & Problem Statement
In institutional FX trading, every order submitted by a client must be checked against a pre-agreed credit limit before it can be accepted and sent for execution. The credit limit expresses the maximum notional USD exposure the firm is willing to carry for that client at any point in time.
1.1 The Centralised Baseline
The canonical implementation uses a single authoritative credit service. Every order triggers a synchronous request/reply round-trip: the trading client sends a CreditCheckRequest, waits for a CreditCheckResponse, and only then submits the order to the execution engine.
  Trading Client A  ──req──►  Credit Service  ──reply──►  Client A  [proceed]
  Trading Client B  ─────────────────req──►  Credit Service  ──reply──►  Client B
  Trading Client C  ──────────────────────────────req──►  Credit Service  ──reply──►  Client C
 
  Burst of 3 orders: Client C waits 3 × RTT before receiving a decision.
1.2 Centralised Pros & Cons
Property
Centralised Model
Consistency
Hard guarantee — credit state is always accurate
SOD recovery
Single service replays trades from one source
Latency (single order)
One RTT (~5–30 µs on Aeron IPC)
Burst latency
Compounds: N orders = N × RTT for last order
Throughput ceiling
Bounded by sequential request/reply
Complexity
Low — single stateful service
1.3 Why Distributed?
The three designs in this document remove or reduce the sequential request/reply bottleneck. Each makes a different trade-off between latency, correctness, and operational complexity. The document covers:
Design 1 — Optimistic Local Cache + Async Correction: lowest latency, eventual consistency, small overshoot window
Design 2 — Token Bucket per Client: sub-microsecond hot path, bounded slack, simple to operate
Design 3 — Atomic Broadcast via Aeron Cluster: exact consistency without request/reply compounding, one sequencer RTT

DESIGN 1 — Optimistic Local Cache + Async Correction
3. Design 1 — Optimistic Local Cache + Async Correction
3.1 Concept
Each trading client holds a read-only cached copy of the current credit consumed, broadcast by the Credit Manager at a configurable interval. All credit checks are pure local arithmetic against this cached value. After accepting an order, the client fires an async trade event to the manager; the manager updates the master state and rebroadcasts.
Key insight: the broadcast interval determines your maximum overshoot window. On Aeron multicast at LAN speeds, this can be as tight as 100–500 µs, bounding the overshoot to a small number of concurrent in-flight orders.

Step 3 — LocalCreditCache (trading client side)
LocalCreditCache.java
package fx.credit.client;
 
import java.util.concurrent.ConcurrentHashMap;
import java.util.concurrent.atomic.AtomicBoolean;
 
public class LocalCreditCache {
 
    // Written by Aeron subscriber thread, read by order check thread
    private final ConcurrentHashMap<String, Long> consumed = new ConcurrentHashMap<>();
    private final ConcurrentHashMap<String, Long> limits   = new ConcurrentHashMap<>();
    // HardStop flag per account — volatile for cross-thread visibility
    private final ConcurrentHashMap<String, AtomicBoolean> hardStop = new ConcurrentHashMap<>();
    private final TradeEventPublisher publisher;
 
    public LocalCreditCache(TradeEventPublisher publisher) {
        this.publisher = publisher;
    }
 
    /**
     * Hot path — called on every incoming order.
     * Must complete in < 1 µs. No I/O, no locks.
     */
    public CreditDecision checkAndAccept(Order order) {
        String aid = order.accountId();
 
        // 1. Hard stop check first (volatile read)
        AtomicBoolean stop = hardStop.get(aid);
        if (stop != null && stop.get()) {
            return CreditDecision.reject(order, DecisionCode.REJECT_HARD_STOP, "Account frozen");
        }
 
        // 2. Snapshot check (may be stale — that is by design)
        long knownConsumed = consumed.getOrDefault(aid, 0L);
        long limit         = limits.getOrDefault(aid, Long.MAX_VALUE);
 
        if (knownConsumed + order.notionalUSD() > limit) {
            return CreditDecision.reject(order, DecisionCode.REJECT_LIMIT_EXCEEDED,
                "Cached consumed=" + knownConsumed + " + notional=" + order.notionalUSD() + " > limit=" + limit);
        }
 
        // 3. Optimistic accept — publish trade event async, no wait
        publisher.publishAsync(new TradeExecutedEvent(order));
        return CreditDecision.accept(order, knownConsumed + order.notionalUSD(), limit - knownConsumed - order.notionalUSD());
    }
 
    // Called by CacheUpdateSubscriber on Aeron multicast thread
    public void onSnapshot(String accountId, long newConsumed, long newLimit) {
        consumed.put(accountId, newConsumed);
        limits.put(accountId, newLimit);
    }
 
    public void onHardStop(String accountId) {
        hardStop.computeIfAbsent(accountId, k -> new AtomicBoolean()).set(true);
    }
}
Step 4 — SnapshotBroadcaster (Credit Manager side)
SnapshotBroadcaster.java
package fx.credit.manager;
 
import io.aeron.Aeron;
import io.aeron.Publication;
import org.agrona.concurrent.UnsafeBuffer;
import java.nio.ByteBuffer;
import java.util.Map;
import java.util.concurrent.Executors;
import java.util.concurrent.ScheduledExecutorService;
import java.util.concurrent.TimeUnit;
 
public class SnapshotBroadcaster {
 
    private static final int STREAM_ID = 1001;
    private final Publication pub;
    private final UnsafeBuffer buf = new UnsafeBuffer(ByteBuffer.allocateDirect(4096));
    private final Map<String, Long> consumed;
    private final Map<String, Long> limits;
    private final ScheduledExecutorService scheduler = Executors.newSingleThreadScheduledExecutor();
 
    public SnapshotBroadcaster(Aeron aeron, String channel,
                               Map<String, Long> consumed, Map<String, Long> limits) {
        this.pub      = aeron.addPublication(channel, STREAM_ID);
        this.consumed = consumed;
        this.limits   = limits;
    }
 
    /** Schedule broadcast every broadcastIntervalMicros microseconds */
    public void start(long broadcastIntervalMicros) {
        scheduler.scheduleAtFixedRate(this::broadcastAll,
            0, broadcastIntervalMicros, TimeUnit.MICROSECONDS);
    }
 
    private void broadcastAll() {
        consumed.forEach((accountId, cons) -> {
            long limit = limits.getOrDefault(accountId, 0L);
            // Simple encoding: [accountIdLen][accountId][consumed][limit]
            int offset = 0;
            byte[] idBytes = accountId.getBytes();
            buf.putInt(offset, idBytes.length);           offset += 4;
            buf.putBytes(offset, idBytes);                offset += idBytes.length;
            buf.putLong(offset, cons);                    offset += 8;
            buf.putLong(offset, limit);                   offset += 8;
            pub.offer(buf, 0, offset); // best-effort — loss is tolerable
        });
    }
}
Step 5 — SOD Loader
SodLoader.java
package fx.credit.manager;
 
import java.sql.*;
import java.util.Map;
 
public class SodLoader {
 
    /**
     * At Start-of-Day, replay today's trade_log per account
     * and populate the Credit Manager's master consumed map.
     */
    public static void load(Connection db,
                            Map<String, Long> consumed,
                            Map<String, Long> limits) throws SQLException {
        // Load limits from reference data
        try (PreparedStatement ps = db.prepareStatement(
                "SELECT account_id, master_limit_usd FROM credit_account WHERE active = TRUE")) {
            ResultSet rs = ps.executeQuery();
            while (rs.next()) {
                limits.put(rs.getString("account_id"), rs.getLong("master_limit_usd"));
            }
        }
 
        // Aggregate today's accepted trades
        try (PreparedStatement ps = db.prepareStatement(
                "SELECT account_id, COALESCE(SUM(notional_usd), 0) AS total " +
                "FROM trade_log " +
                "WHERE decided_at >= CURRENT_DATE AND decision_code = 'ACCEPT' " +
                "GROUP BY account_id")) {
            ResultSet rs = ps.executeQuery();
            while (rs.next()) {
                consumed.put(rs.getString("account_id"), rs.getLong("total"));
            }
        }
    }
}
DESIGN 2 — Token Bucket with Centralised Top-Up
4. Design 2 — Token Bucket with Centralised Top-Up
4.1 Concept
The Credit Manager pre-grants each trading client a "bucket" — a finite quota of notional they may consume without any network call. The client deducts from its local bucket atomically. When the bucket drops below a configurable threshold, the client requests a top-up from the manager. Only the top-up path involves a network call; the hot path is entirely in-process.
Key insight: top-up requests are rare relative to order flow. A bucket sized at $500K consumed by $50K average orders yields 10 orders per bucket — top-up overhead is 10% of orders at most. In practice, buckets refill faster than they drain.

Step 1 — TokenBucketShard (client side)
TokenBucketShard.java
package fx.credit.client;
 
import java.util.concurrent.atomic.AtomicLong;
 
public class TokenBucketShard {
 
    private final AtomicLong bucketCents;  // remaining credit in USD cents
    private final String     accountId;
    private final String     clientId;
    private final long       topUpThresholdCents;
    private final TopUpRequester topUpRequester;
 
    // Prevent concurrent top-up storms
    private volatile boolean topUpInFlight = false;
 
    public TokenBucketShard(String accountId, String clientId,
                            long initialBucketCents, long topUpThresholdCents,
                            TopUpRequester topUpRequester) {
        this.bucketCents         = new AtomicLong(initialBucketCents);
        this.accountId           = accountId;
        this.clientId            = clientId;
        this.topUpThresholdCents = topUpThresholdCents;
        this.topUpRequester      = topUpRequester;
    }
 
    /**
     * Hot path. Single CAS loop, no I/O.
     */
    public CreditDecision checkAndDeduct(Order order) {
        long notional = order.notionalUSD();
 
        while (true) {
            long current = bucketCents.get();
            if (current < notional) {
                // Bucket exhausted — trigger top-up (async) and reject or queue
                triggerTopUpIfNotInFlight();
                return CreditDecision.reject(order, DecisionCode.REJECT_SHARD_EXHAUSTED,
                    "Bucket exhausted. Top-up in flight: " + topUpInFlight);
            }
            if (bucketCents.compareAndSet(current, current - notional)) {
                // Successful deduction
                maybeRequestTopUp(current - notional);
                return CreditDecision.accept(order, -1, current - notional);
            }
            // CAS lost to concurrent thread on same client — retry
        }
    }
 
    /** Called async when top-up grant arrives from Credit Manager */
    public void onTopUpGrant(long grantedCents) {
        bucketCents.addAndGet(grantedCents);
        topUpInFlight = false;
    }
 
    private void maybeRequestTopUp(long remaining) {
        if (remaining < topUpThresholdCents && !topUpInFlight) {
            triggerTopUpIfNotInFlight();
        }
    }
 
    private void triggerTopUpIfNotInFlight() {
        // Optimistic CAS on boolean to avoid duplicate requests
        if (!topUpInFlight) {
            topUpInFlight = true;
            topUpRequester.requestAsync(new TopUpRequest(accountId, clientId,
                /* requestedCents */ 500_000_00L));
        }
    }
}
Step 2 — CreditManager (top-up handler)
CreditManager.java — Design 2
package fx.credit.manager;
 
import java.util.Map;
import java.util.concurrent.ConcurrentHashMap;
 
public class CreditManager {
 
    private final Map<String, Long> masterLimit    = new ConcurrentHashMap<>();
    private final Map<String, Long> masterConsumed = new ConcurrentHashMap<>();
    // Total bucket credit currently outstanding to all clients per account
    private final Map<String, Long> totalAllocated = new ConcurrentHashMap<>();
 
    private static final double ALLOCATION_CAP = 0.80; // never grant more than 80% of limit
 
    /**
     * Called when a TopUpRequest arrives from a client.
     * Returns the actual grant — may be less than requested if headroom is tight.
     */
    public TopUpGrant handleTopUpRequest(TopUpRequest req) {
        String aid = req.accountId();
        long   limit     = masterLimit.getOrDefault(aid, 0L);
        long   consumed  = masterConsumed.getOrDefault(aid, 0L);
        long   allocated = totalAllocated.getOrDefault(aid, 0L);
 
        long cap       = (long)(limit * ALLOCATION_CAP);
        long headroom  = cap - consumed - allocated;
        long grant     = Math.max(0, Math.min(req.requestedCents(), headroom));
 
        if (grant > 0) {
            totalAllocated.merge(aid, grant, Long::sum);
        }
 
        return new TopUpGrant(req.accountId(), req.clientId(), grant);
    }
 
    /** Called when async TradeExecutedEvent arrives */
    public void onTradeExecuted(TradeExecutedEvent evt) {
        masterConsumed.merge(evt.accountId(), evt.notionalUSD(), Long::sum);
        checkBreach(evt.accountId());
    }
 
    private void checkBreach(String accountId) {
        long consumed = masterConsumed.getOrDefault(accountId, 0L);
        long limit    = masterLimit.getOrDefault(accountId, Long.MAX_VALUE);
        if (consumed > limit) {
            publishHardStop(accountId, consumed - limit);
        }
    }
 
    private void publishHardStop(String accountId, long overshoot) {
        // Publish HardStopEvent via Aeron to all clients
        System.err.println("BREACH: account=" + accountId + " overshoot=" + overshoot);
    }
}
DESIGN 3 — Atomic Broadcast / Total Order via Aeron Cluster
5. Design 3 — Atomic Broadcast / Total Order via Aeron Cluster
5.1 Concept
Rather than distributing state, this design distributes the decision itself. All orders are funnelled through an Aeron Cluster sequencer that stamps each with a monotonic sequence number and replicates it to all cluster nodes via Raft. Every node runs identical deterministic credit check logic against the same ordered stream. Because all nodes process the same events in the same order, they maintain identical state — there is no need for cross-node coordination.
Key insight: consistency is achieved not by centralising the check, but by guaranteeing that every node sees every event in exactly the same order. The sequencer stamps and replicates; it does not check. Checking happens locally on each node.
5.2 What the Sequencer Does vs What It Does Not Do
The sequencer DOES
The sequencer does NOT
Assigns monotonic sequence numbers
Perform any credit check
Replicates event to all Raft followers
Access any database or external service
Commits only after quorum acknowledgement
Aggregate or compare state across orders
Elects a new leader on node failure
Know the current credit consumed amount
Provides ordered egress stream to all subscribers
Have any business logic whatsoever

5.6 Critical Constraint: Determinism
The ClusteredService.onSessionMessage() callback MUST be deterministic. If any node produces a different result for the same input — due to wall-clock reads, non-deterministic data structures, or external I/O — nodes will diverge and the cluster will become inconsistent. This is the single most important implementation rule for Design 3.
Allowed inside ClusteredService
FORBIDDEN inside ClusteredService
HashMap / ArrayList (deterministic iteration)
System.currentTimeMillis() or Instant.now()
Cluster-provided timestamp (from onSessionMessage)
Random / UUID.randomUUID()
Pure arithmetic and comparisons
Database reads or writes
Publishing to egress
REST or gRPC calls
Reading from internal maps built from prior events
Non-deterministic comparators (HashMap iteration order on JDK <8)
Snapshot / restore logic
Logging frameworks that may buffer differently per node

package fx.credit.cluster;
 
import java.util.HashMap;
import java.util.Map;
 
/**
 * Pure in-memory state — no I/O, fully deterministic.
 * Identical instance on all 3 cluster nodes.
 */
public class CreditState {
 
    // Use LinkedHashMap where iteration order matters for snapshotting
    private final Map<String, Long> masterLimit    = new HashMap<>();
    private final Map<String, Long> consumed       = new HashMap<>();
    private final Map<String, Boolean> hardStop    = new HashMap<>();
 
    public CreditDecisionCode applyOrder(String accountId, long notionalUSD) {
        if (Boolean.TRUE.equals(hardStop.get(accountId))) {
            return CreditDecisionCode.REJECT_HARD_STOP;
        }
        long limit = masterLimit.getOrDefault(accountId, 0L);
        long cons  = consumed.getOrDefault(accountId, 0L);
 
        if (cons + notionalUSD > limit) {
            return CreditDecisionCode.REJECT_LIMIT_EXCEEDED;
        }
        // Mutate state — identical on all nodes
        consumed.put(accountId, cons + notionalUSD);
        return CreditDecisionCode.ACCEPT;
    }
 
    public void applyMarginUpdate(String accountId, long newLimitUSD) {
        // Margin updates arrive as sequenced commands through ingress
        masterLimit.put(accountId, newLimitUSD);
    }

        hardStop.put(accountId, Boolean.TRUE);
    }
 
    // SOD load — called before cluster opens for ingress
    public void loadAccount(String accountId, long limitUSD, long sodConsumedUSD) {
        masterLimit.put(accountId, limitUSD);
        consumed.put(accountId, sodConsumedUSD);
    }

Step 4 — CreditClusteredService
CreditClusteredService.java
package fx.credit.cluster;
 
import io.aeron.cluster.codecs.CloseReason;
import io.aeron.cluster.service.ClientSession;
import io.aeron.cluster.service.Cluster;
import io.aeron.cluster.service.ClusteredService;
import io.aeron.logbuffer.Header;
import org.agrona.DirectBuffer;
import org.agrona.concurrent.UnsafeBuffer;
import java.nio.ByteBuffer;
 
public class CreditClusteredService implements ClusteredService {
 
    private final CreditState    state = new CreditState();
    private final MessageEncoder encoder = new MessageEncoder();
    private Cluster              cluster;
    private final UnsafeBuffer   egressBuf =
        new UnsafeBuffer(ByteBuffer.allocateDirect(256));
 
    @Override
    public void onStart(Cluster cluster, Image snapshotImage) {
        this.cluster = cluster;
        if (snapshotImage != null) {
            // Restore state from Aeron Archive snapshot
            restoreFromSnapshot(snapshotImage);
        } else {
            // SOD: load from trade_log via SodSnapshotLoader
            SodSnapshotLoader.load(state);
        }
    }
 
    /**
     * Called by Aeron Cluster for every sequenced message — in strict order.
     * MUST be deterministic. MUST NOT perform I/O.
     * timestamp is cluster-provided — safe to use (same value on all nodes).
     */
    @Override
    public void onSessionMessage(ClientSession session, long timestamp,
                                 DirectBuffer buffer, int offset, int length,
                                 Header header) {
        // Decode message type
        byte msgType = buffer.getByte(offset);
 
        switch (msgType) {
            case MessageType.ORDER_CHECK -> handleOrderCheck(session, buffer, offset + 1, timestamp);
            case MessageType.MARGIN_UPDATE -> handleMarginUpdate(buffer, offset + 1);
            case MessageType.HARD_STOP     -> handleHardStop(buffer, offset + 1);
        }
    }
 
    private void handleOrderCheck(ClientSession session,
                                  DirectBuffer buf, int offset, long timestamp) {
        // Decode order fields
        String accountId  = decodeString(buf, offset);  offset += accountId.length() + 4;
        String orderId    = decodeString(buf, offset);  offset += orderId.length() + 4;
        long   notional   = buf.getLong(offset);
 
        // Run deterministic check against in-memory state
        CreditDecisionCode code = state.applyOrder(accountId, notional);
 
        // Encode decision into egress buffer
        int len = encoder.encodeDecision(egressBuf, 0, orderId, accountId, code, timestamp);
 
        // Publish to egress — multicast to all subscribers
        cluster.idleStrategy().reset();
        while (session.offer(egressBuf, 0, len) < 0) {
            cluster.idleStrategy().idle();
        }
    }
 
    private void handleMarginUpdate(DirectBuffer buf, int offset) {
        String accountId  = decodeString(buf, offset); offset += accountId.length() + 4;
        long   newLimit   = buf.getLong(offset);
        // Update credit state deterministically
        state.applyMarginUpdate(accountId, newLimit);
    }
 
    private void handleHardStop(DirectBuffer buf, int offset) {
        String accountId = decodeString(buf, offset);
        state.applyHardStop(accountId);
    }
 
    @Override
    public void onTakeSnapshot(ExclusivePublication snapshotPublication) {
        // Periodically called by Aeron Cluster to checkpoint state
        byte[] snap = state.toSnapshot();
        UnsafeBuffer snapBuf = new UnsafeBuffer(snap);
        while (snapshotPublication.offer(snapBuf, 0, snap.length) < 0) {
            Thread.onSpinWait();
        }
    }
 
    @Override
    public void onRoleChange(Cluster.Role newRole) {}
    @Override
    public void onTerminate(Cluster cluster) {}
    @Override
    public void onSessionOpen(ClientSession session, long timestamp) {}
    @Override
    public void onSessionClose(ClientSession session, long timestamp, CloseReason reason) {}
 
    private void restoreFromSnapshot(Image image) {
        // Read snapshot bytes from Aeron Image, delegate to CreditState.fromSnapshot()
    }
 
    private String decodeString(DirectBuffer buf, int offset) {
        int len = buf.getInt(offset);
        byte[] bytes = new byte[len];
        buf.getBytes(offset + 4, bytes);
        return new String(bytes);
    }
}

Step 6 — Egress Subscriber (trading client receives decisions)
CreditEgressSubscriber.java
package fx.credit.gateway;
 
import io.aeron.cluster.client.AeronCluster;
import io.aeron.cluster.client.EgressListener;
import org.agrona.DirectBuffer;
 
public class CreditEgressSubscriber implements EgressListener {
 
    private final OrderRouter orderRouter; // dispatches Fill/Reject to local handlers
 
    public CreditEgressSubscriber(OrderRouter orderRouter) {
        this.orderRouter = orderRouter;
    }
 
    @Override
    public void onMessage(long clusterSessionId, long timestamp,
                          DirectBuffer buffer, int offset, int length,
                          Header header) {
        // Decode decision
        String orderId = decodeOrderId(buffer, offset);
        CreditDecisionCode code = decodeCode(buffer, offset);
 
        // Route to waiting order handler
        orderRouter.onDecision(orderId, code);
    }
 
    /**
     * AeronCluster client — connects to cluster ingress and subscribes to egress.
     * Submit orders via cluster.offer(); receive decisions via this.onMessage().
     */
    public static AeronCluster connectToCluster() {
        return AeronCluster.connect(new AeronCluster.Context()
            .egressListener(new CreditEgressSubscriber(new OrderRouter()))
            .ingressChannel("aeron:udp")
            .ingressEndpoints("0=localhost:9010,1=node2:9010,2=node3:9010")
            .egressChannel("aeron:udp?endpoint=localhost:9021"));
    }
 
    private String decodeOrderId(DirectBuffer buffer, int offset) {
        int len = buffer.getInt(offset);
        byte[] bytes = new byte[len];
        buffer.getBytes(offset + 4, bytes);
        return new String(bytes);
    }
 
    private CreditDecisionCode decodeCode(DirectBuffer buffer, int offset) {
        // Skip orderId and accountId, read decision byte
        return CreditDecisionCode.values()[buffer.getByte(offset)];
    }
}

Compare-And-Swap — single atomic CPU instruction used for lock-free state updates
Credit Limit
Maximum notional USD exposure a client is permitted at any point in time
Egress
The outbound stream from Aeron Cluster to external subscribers carrying decisions and events
Ingress
The inbound channel into Aeron Cluster through which client messages are sequenced
SOD
Start of Day — the process of loading previous trades and positions before opening for new orders
Notional
The face value of an FX order in USD equivalent, used as the unit of credit consumption
Hard Stop
An immediate freeze on all new orders for an account, triggered on confirmed credit breach
Token Bucket
A pre-allocated quota of credit assigned to a single trading client for autonomous consumption
Total Order
A global ordering of all events such that every observer processes them in exactly the same sequence
ClusteredService
The Aeron Cluster interface that a developer implements to define the replicated state machine logic
